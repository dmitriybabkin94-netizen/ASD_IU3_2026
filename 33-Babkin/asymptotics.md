**Задачи:** №7, 8, 13, 19, 34, 38 и 43.

## Обозначения и правила оценки

- `n` — длина массива; в №19 `m` — длина второго массива.
- `p` и `q` — количества положительных и отрицательных чисел в №8; `p + q ≤ n`.
- `s = k % n` — нормализованный сдвиг в №38 при `n > 0`.
- `T` — время работы, `S` — вспомогательная память алгоритма.
- `O` обозначает верхнюю оценку роста затрат, `Θ` — точный порядок роста.

Доступ к элементу массива, сравнение и арифметика с `int` или `long` считаются операциями
постоянной стоимости. Оценки ниже относятся к допустимым входам.
Память входных массивов не включается во вспомогательную память. Новый результат учитывается
отдельно. Для преобразований на месте новый массив результата не выделяется.

## №7. Второй максимум

Файл: [SecondMaximum.java](src/main/java/ru/bmstu/lab1/task_7/SecondMaximum.java).

Первый элемент задаёт начальный максимум. Цикл проходит остальные `n - 1` элементов.
На каждой итерации выполняется ограниченное константой число сравнений и присваиваний;
вложенных циклов и сортировки нет. Алгоритм всегда просматривает весь массив.

Следовательно, `T(n) = Θ(n - 1) + O(1) = Θ(n)`.

Переменные `maximum`, `secondMaximum`, `hasSecond`, `index` и `value` занимают фиксированный
объём независимо от `n`: `S(n) = O(1)`. Возвращается одно число за `O(1)` памяти.
Исходный массив не меняется, его копия не создаётся.

## №8. Фильтрация по знаку

Файл: [SignFilter.java](src/main/java/ru/bmstu/lab1/task_8/SignFilter.java).

Первый проход обрабатывает `n` элементов и подсчитывает размеры двух групп.
Выделение и начальная инициализация массивов длины `p` и `q` требуют `O(p + q)` времени.
Второй проход снова рассматривает `n` элементов и записывает в результат `p + q` чисел.

Таким образом, `T(n) = Θ(n) + O(p + q) + Θ(n) = Θ(n)`, поскольку `p + q ≤ n`.

Счётчики и индексы занимают `O(1)` вспомогательной памяти. Массивы результата требуют
`O(p + q)` памяти, объект `SignGroups` — `O(1)`. С учётом результата дополнительная память
в худшем случае равна `O(n)`. Исходный массив не меняется.

## №13. Сортировка выбором

Файл: [SelectionSort.java](src/main/java/ru/bmstu/lab1/task_13/SelectionSort.java).

Внешний цикл выбирает позиции от `0` до `n - 2`. Для позиции `i` внутренний цикл сравнивает
оставшиеся `n - i - 1` элементов с текущим минимумом. Общее число сравнений элементов:

C(n) = (n - 1) + (n - 2) + ... + 1 = n(n - 1) / 2.

Для каждой из `n - 1` позиций выполняется один обмен за `O(1)`. Поэтому
`T(n) = Θ(n(n - 1) / 2) + O(n) = Θ(n²)`.
Количество сравнений не зависит от начального порядка: оценка одинакова для лучшего
и худшего случаев, включая уже отсортированный массив.

Индексы и временное значение при обмене занимают `O(1)` памяти. Сортировка выполняется
в исходном массиве: `S(n) = O(1)`, новый массив результата не нужен.

## №19. Слияние двух отсортированных массивов

Файл: [SortedMerge.java](src/main/java/ru/bmstu/lab1/task_19/SortedMerge.java).

Хотя в коде три цикла, они не вложены друг в друга. В первом цикле на каждом шаге увеличивается
ровно один из двух входных индексов. Два следующих цикла дописывают ещё не перенесённые
элементы. Каждый из `n + m` элементов записывается ровно один раз.

Создание результата длины `n + m` и его заполнение требуют `Θ(n + m)` времени.
Итого `T(n, m) = Θ(n + m)`.

Три индекса занимают `O(1)` вспомогательной памяти. Новый выходной массив занимает
`O(n + m)` памяти, поэтому с учётом результата дополнительная память равна `O(n + m)`.
Входные массивы не копируются и не меняются.

## №34. Максимальная сумма подмассива

Файл: [MaximumSubarray.java](src/main/java/ru/bmstu/lab1/task_34/MaximumSubarray.java).

После инициализации первым элементом алгоритм Кадане выполняет `n - 1` итераций.
Каждая итерация содержит одно сложение, два выбора максимума и присваивания за `O(1)`.
Все элементы рассматриваются независимо от их знаков.

Следовательно, `T(n) = Θ(n - 1) + O(1) = Θ(n)`.

Две суммы типа `long` и индекс занимают фиксированный объём: `S(n) = O(1)`.
Ответ — одно число за `O(1)` памяти, входной массив не меняется.
Тип `long` имеет постоянный размер: его использование не меняет порядок сложности.
При `n ≤ 99999` модуль суммы не превышает `99999 × 2147483648`, что помещается в `long`.

## №38. Циклический сдвиг влево

Файл: [LeftRotation.java](src/main/java/ru/bmstu/lab1/task_38/LeftRotation.java).

Нормализация `s = k % n` занимает `O(1)`, так как `k` имеет фиксированный тип `long`.
Если массив пуст или `s = 0`, метод завершится за `O(1)` без разворотов.

При `0 < s < n` разворачиваются две части длины `s` и `n - s`, затем весь массив длины `n`.
Разворот участка длины `l` выполняет `floor(l / 2)` обменов. Общее число обменов:

C(n, s) = floor(s / 2) + floor((n - s) / 2) + floor(n / 2) ≤ n.

В частности, последний разворот уже требует `Θ(n)` операций. Поэтому для ненулевого
нормализованного сдвига время равно `Θ(n)`, общий верхний предел — `O(n)`.
Количество полных оборотов в `k` не увеличивает число итераций.

Используются индексы, сдвиг и временное число для обмена: `S(n) = O(1)`.
Метод разворота вызывается последовательно и не рекурсивно. Новый массив не создаётся.

## №43. Перемещение нулей в конец

Файл: [ZeroMover.java](src/main/java/ru/bmstu/lab1/task_43/ZeroMover.java).

Первый цикл читает все `n` элементов. Обозначим количество ненулевых значений через `r`:
в этом цикле выполняется `r` записей. Второй цикл записывает `n - r` нулей.
Следовательно, суммарно производится `n` чтений и `r + (n - r) = n` записей.

Отсюда `T(n) = Θ(n)`, в том числе для массива без нулей или состоящего только из нулей.

Индекс записи и текущее значение занимают фиксированный объём: `S(n) = O(1)`.
Результат размещается в исходном массиве, отдельный выходной массив не выделяется.

## Затраты консольного ввода и вывода

Выше оценены алгоритмические методы. Полная консольная программа дополнительно хранит входной
массив за `O(n)` памяти; в №19 два входных массива занимают `O(n + m)`.
Метод `ConsoleInput.printArray` создаёт `StringBuilder`, занимающий `O(r)` памяти и времени
для `r` выводимых чисел: ширина каждого значения `int` ограничена константой.
Для числового ответа №7 и №34 объём вывода равен `O(1)`.

Чтение массива и вывод массива требуют линейного времени. Поэтому для полной программы №38
время остаётся `Θ(n)` даже при сдвиге на ноль, а полная память преобразований на месте с учётом
ввода и форматирования вывода равна `O(n)`. Это не меняет оценку `O(1)` вспомогательной памяти
самих алгоритмов, выполняющих преобразования исходного массива.
